## Block 2: prove the piece algebra on the CPU (~1 h), KERNEL_IDEA §7 step 1

Before any CUDA: check that "sum over (a, k) of independent pieces" gives the same `y` as
the reference.

```
   for t, a, k:                                      FP64, plain PyTorch loops,
       S1[j,p,b] = Σ_i  x[i,j,k,t]  · A[a,p,i,b]      small modes first (unequal sizes),
       S2[p,q,c] = Σ_jb S1[j,p,b]   · B[b,q,j,c]      then the real modes
       y[p,q,r,t] += Σ_c S2[p,q,c]  · C[c,r,k,a]
   compare with tr_forward_reference and the dense oracle
```

**Done when:** max error ~1e-12 in FP64 against the oracle, for R = 8 and R = 16. This
file is also the **oracle for every later kernel version**.

## Block 3: CUDA v0, correct and simple (~3 h), KERNEL_IDEA §7 step 2

```
   grid:   one block per (a, k, token tile)          tt = 1 to start
   block:  load x slice, A[a], B, C[k,a] → shared memory
           stage 1, 2, 3 as plain loops (FP32 math, no Tensor Cores)
           atomicAdd partial y → FP32 workspace
   then:   convert FP32 workspace → FP16 output
   host:   one C++ function, on at::cuda::getCurrentCUDAStream()
```

Order of work:

1. Kernel + a standalone test against the block 2 oracle (small modes, then real).
2. Wire into `prepare_optimized` via `torch.utils.cpp_extension.load` (build for sm_86 on
   the laptop; `sm_90` later).
3. `pytest -q` in the project (21 tests must stay green, with no dense W anywhere).
4. Run the harness once on the laptop with `--device cuda:0`. The row that matters is
   `factorized_optimized` against `factorized_reference`.

**Done when:** pytest green; the harness shows `factorized_optimized` passing correctness
in all five cases; the profiler trace shows **our** kernel name.

The speed of v0 does not matter. Record it anyway: it is the first data point for the model.
